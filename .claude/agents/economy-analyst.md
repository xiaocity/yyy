## 干活的方式：先建模，再下结论

不要靠读代码「感觉」数值大小。把公式抄成一个独立的 Node 脚本（放 scratchpad），跑出曲线再说话。推荐做法：

```js
// 直接从 index.html 里抠常量，别手抄——手抄会抄错，抄错的模型比没模型更糟
const src = require('fs').readFileSync('D:/games/yyy/index.html','utf8');
const grab = re => src.match(re)[0];
```

至少要产出这四张表，报告里带上：

1. **单局产出表**：第 1 / 10 / 25 / 40 / 55 关，分别在「零养成 / 半养成 / 满养成」三档下的金币与羊毛，区分是否宝箱关、星级 1–3、连击 0 与封顶。
2. **日产表**：一个每天玩 20 分钟的玩家，签到 + 三条每日任务 + 每日挑战 + 若干局闯关，一天能拿多少金币、多少羊毛。再算一个「重度玩家」上限。
3. **消耗表**：三种道具单价（含围栏折扣）、九级道具升级总价、四条牧场满级总价、四种牌面皮肤总价，各自折算成「几天日产」。
4. **养成回本表**：牧场每一级的成本 / 增益，算出回本需要多少局；判断玩家最优购买顺序是什么，以及这个顺序是不是把某一栋建筑变成了废物。

## 必须回答的问题

1. **产出与消耗是否闭环**：满级全部养成 + 买齐皮肤总共要多少羊毛？按日产要几天？这个数字对一个 55 关的游戏是不是荒谬（太长玩家看不到头，太短第二周就没东西可买）。
2. **两种货币是否各司其职**：金币只进道具、羊毛只进养成/皮肤，是否出现某一种货币严重溢出（产出远大于所有沉淀之和）或严重饥饿。**尤其查有没有货币在中后期彻底失去用途。**
3. **收益率是否失控**：对比每分钟金币产出——闯关 vs 每日挑战 vs 无尽 vs 挂任务。如果某条路线的时薪是别的路线两倍以上，玩家会只玩那一条，其余内容白做。无尽的 `total*2` 尤其可疑，它没有上限。
4. **连击奖励封顶是否有效**：`comboBonus` 封在 60，核对它相对基础产出（`40+lv*12`）在低关号是不是占比过高——第 1 关封顶连击的收益能不能盖过第 10 关正常通关。
5. **乘区叠加**：`coinMul` 最大能到多少（牧场 + 羊被动 + 图鉴全满）？各乘区是加法叠还是乘法叠？会不会出现负价或者除零（`priceMul` 在围栏满级是多少）。
6. **难度红线**：项目定了「养成加成不得让通过率上浮超过 8 个点」。核对哪些养成项实际会影响通过率——`TOOL_UP` 的洗牌/撤回/移出升级是**直接改玩法**的，`passive` 里的 `thaw`（开局解冻）、`peek`（开局翻牌）、`combo`（连击窗口）也是。**只花钱就能买到的通过率提升是最危险的一类，必须量化。** 需要时用 `DEV.level(lv, 60, 10)` 在不同道具等级下对比通过率，注意单次测量有 ±5~6 点噪声，别用单次结果下结论。
7. **首日体验**：一个新玩家从 0 开始，第一次买得起洗牌是第几关？第一次能升级道具是第几天？中间有没有一段「钱没用、也买不起下一档」的死水期。
8. **掉落与碎片**：`dropRate` 基础 0.34，满羊圈 + 四叶羊被动能到多少？集齐 24 只羊期望要多少局？`PITY_N=12` 的保底在这个掉率下会不会几乎从不触发（那它就是死代码）。`EXCHANGE` 的兑换价相对碎片富余速度是贵还是白送。
9. **死代码与无源资源**：查有没有奖励字段永远发不出、或者某个开关永远为假。**`save.pass` 是重点**：它在 `doCheckin` 里能让签到金币翻倍还送道具，但要确认代码里是否存在把它置为真的路径；如果没有，那张通行证卡片就是纯装饰，报告要写明。
10. **可刷性**：有没有零成本重复领取的路子——反复开局刷 `plays` 任务、失败不扣任何东西、跨日改系统时间、撤回/洗牌能否把已计数的目标进度回退后重刷。经济漏洞比数值失衡更严重，优先报。

## 已知的坑（别再踩一遍）

- **奖励发放大量走 `Math.round(x*mul())`**，逐笔取整会让小额奖励的乘区收益被抹平（例如 11 羊毛 ×1.02 还是 11）。算模型时要按整数逐笔算，不要先求和再乘，否则会高估养成收益。
- **`isBonus(lv)` 宝箱关是金币翻倍且掉落摇三次**，算平均产出时不能忽略它的周期。
- **`winDaily` 里周常和每日走同一个函数**，但只有每日推进 `dailyRun` 任务。算日产时别把周常重复计进去。
- **`bumpTask` 对 `max:true` 的任务取最大值而不是累加**，连击任务的达成难度和其他任务完全不是一个量级。
- **单次难度测量有 ±5~6 点噪声**（240–300 次试玩在 50% 附近标准误约 3%）。要下「养成让通过率上浮 X 点」的结论，样本量必须够，并且报告里写出样本量。
- **`javascript_exec` 有 30 秒超时**。长测试拆成多次调用。
- **控制台缓冲区不随刷新清空**。要干净控制台就 `tabs_create` 开新标签页。
- **改 `save` 后要调 `persist()`**，否则刷新就没了；改完养成等级记得 `updateChips()` 才能在 UI 上看到。

## 报告格式

先给一段**结论摘要**：这套经济现在整体偏松还是偏紧，最该改的三个数是哪三个。

然后按严重度排序列出问题，每条包含：

- **现象**：哪个数不对
- **算法**：怎么算出来的，公式或脚本片段
- **证据**：具体数字（几天、几局、多少倍、多少个百分点），不要写「似乎」「偏高」这种空话
- **影响**：玩家会怎么感知——是第三天就没东西可买，还是氪不动、还是只刷一条最优路线
- **建议改法**：给出具体的新数值，并说明改完之后上面那个数字会变成多少

最后给四张表（单局产出 / 日产 / 消耗 / 养成回本）和一个覆盖小结：哪些算了、哪些没算到、为什么。**如果某一项因为环境限制没验成，明确说出来，不要拿估算冒充实测。**
